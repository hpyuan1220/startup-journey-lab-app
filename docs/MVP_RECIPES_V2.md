# MVP 步驟包 v2：選了商業痛點之後，打開工具、貼一段 prompt、做出小型 MVP（2026-10-17 定案草案）

對學生用詞：步驟包、小型 MVP。對外不講「步驟包」。

## 最簡路徑（全班必做）：九張卡都用「Gem＋一段 prompt」做出 MVP v1
學生只做四步，app 只顯示 prompt 與四格勾選：
1. 打開 Gemini → Gems → 新增 Gem。
2. 貼上 app 給的「指示」四段（身分／知識／規則／格式），已依他的卡與第一個客戶預填，可改、可還原。
3. 上傳一份知識文件：店的 FAQ、SOP、價目、規則（學生自己整理，不放客人個資）。
4. 測十句（五句文件有的、三句沒有的、兩句刁難的）→ 調整 → 取得分享連結 → 貼回 app（連結＋三張測試截圖）。

| 卡 | 這個 Gem 做什麼 | 老闆怎麼用 |
|---|---|---|
| 1 餐飲小店 | 店員問 SOP；交班時把口頭講的整理成缺貨備註 | 店員跟它講一分鐘，複製貼給老闆 |
| 2 零工短班 | 店長丟「週三晚缺一人」→ 產生給學生群的代班訊息＋回覆整理 | 店長複製到 LINE 群 |
| 3 網拍賣家 | 貼客人訊息 → 回覆草稿（含退貨規則） | 30 秒回一則 |
| 4 旅宿 | 問房 FAQ＋產生「明天入住確認」訊息 | 老闆複製到 LINE 發 |
| 5 健身／筋膜 | 教練貼「這位學員本週三個動作」→ 產生提醒訊息（只轉達，不給建議） | 教練複製發送 |
| 6 獲客漏斗 | 貼 Google 評論 → 回覆草稿；貼 IG 私訊 → 回覆＋預約連結 | 老闆改兩個字送出 |
| 7 小店 CRM | 貼熟客表 → 本週該回訪誰、每人一句訊息 | 老闆複製到 LINE |
| 8 銀髮家屬 | 貼本週群組訊息 → 交接摘要＋回診用藥清單（不判斷） | 家屬轉貼 |
| 9 壯年老手 | 老手的 SOP 當知識 → 新人問答 | 新人問它 |

每一個都是「老闆貼進來、它產出、老闆複製出去」：沒有串接、沒有程式，一個晚上做得完。少了「自動」，但足以驗證老闆要不要——他願不願意每天貼東西給它、用它的輸出，就是答案（YC：先手動服務）。

## 兩條路（Week 7 開場，組自己勾；老師定案 2026-10-18）

| | 簡單版：AI 小幫手 | 代理版：會自己動的 AI 代理 |
|---|---|---|
| 它會做什麼 | 老闆貼進來 → 它回答或產出 → 老闆複製出去 | 時間到或表單一送出 → 自己讀資料、自己寫訊息、自己寄出或寫回表 |
| 用什麼 | Gemini Gem | Google 試算表＋Apps Script 呼叫 Gemini API（金鑰從 AI Studio 免費取得） |
| 幾步、多久 | 4 步、一個晚上 | 8 步、兩個晚上 |

| 課堂 | Week 7 分站只教簡單版 | Week 7 就開放，靠 app 八步＋老師課後一次線上答疑；加分 |

### 代理版八步（每步 app 都給可複製的東西與要貼回的證明）
| 步 | 做什麼 | app 給什麼 | 證明 |
|---|---|---|---|
| 1 | 到 AI Studio 取得 Gemini API 金鑰（免費） | 連結＋提醒：金鑰只貼在第 3 步，不進試算表、不給別人、不進 repo | 勾選 |
| 2 | 建立 app 給的範本試算表副本（已含 Apps Script；欄位：日期、對象、Email、資料、狀態） | 「建立副本」連結 | 副本連結 |
| 3 | 金鑰放進指令碼屬性 | 擴充功能 → Apps Script → 專案設定 → 指令碼屬性 → 新增 `GEMINI_API_KEY` | 截圖（遮住金鑰） |
| 4 | 改 PROMPT：代理要怎麼寫訊息 | 依這張卡預填的四段指示 | 貼回改後的 PROMPT |
| 5 | 執行一次、完成授權（試算表＋Gmail） | 按「執行」→ 允許 | 第一封測試信截圖 |
| 6 | 設觸發：每天幾點，或表單送出就跑 | 觸發條件 → 新增 → 時間驅動／表單提交 | 截圖 |
| 7 | 測兩天：自己寄、沒重複、內容對 | 三項檢查清單 | 兩封信截圖 |
| 8 | 交付包 | 試算表連結（老闆填）、一句話說明、「怎麼關掉」 | 三樣連結 |

範本程式核心（副本裡已有，學生只改 PROMPT 與欄位名；模型名稱以 AI Studio 當時列出的為準）：
```javascript
const PROMPT = `你是〔店名〕的小幫手。用繁體中文、兩句以內、語氣像店員。
依下面的資料寫一則要寄給〔對象〕的訊息，只寫訊息本文：`;

function runAgent() {
  const key = PropertiesService.getScriptProperties().getProperty('GEMINI_API_KEY');
  const sheet = SpreadsheetApp.getActive().getSheetByName('工作表1');
  const rows = sheet.getDataRange().getValues();
  const today = new Date().toDateString();
  rows.forEach((r, i) => {
    if (i === 0 || r[4] === '已寄' || new Date(r[0]).toDateString() !== today) return;
    const text = askGemini(key, PROMPT + '\n' + r[3]);
    MailApp.sendEmail(r[2], `給 ${r[1]} 的提醒`, text + '\n（小幫手自動寄出）');
    sheet.getRange(i + 1, 5).setValue('已寄');
  });
}

function askGemini(key, prompt) {
  const url = 'https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent?key=' + key;
  const res = UrlFetchApp.fetch(url, { method: 'post', contentType: 'application/json',
    payload: JSON.stringify({ contents: [{ parts: [{ text: prompt }] }] }) });
  return JSON.parse(res.getContentText()).candidates[0].content.parts[0].text.trim();
}
```

## 五個基礎步驟包（R1–R5）

### R1　Gem：會回答的小助手（agent）　約 40 分鐘
用在：客人問、店員問、新人問、評論回覆草稿、訊息草稿。
1. 準備知識：一份 Google 文件，內容是店的 FAQ／SOP／價目／規則，一條一行，不放個資（客人姓名、電話）。
2. 開 gemini.google.com → 左側「Gems」→「新增 Gem」。
3. 名稱：「〔店名〕小幫手」。指示欄貼四段：
   - 身分：你是〔店名〕的店員助理，只回答跟這家店有關的問題。
   - 知識：只用我上傳的文件回答；文件沒有的就說「這個要問老闆」，不要編。
   - 規則：用繁體中文、兩句以內、語氣像店員；遇到〔退貨／客訴／價格爭議〕一律回「我幫您轉給老闆」。
   - 格式：先給答案，再給一句下一步（例：「要幫您預約嗎？」）。
4. 「上傳檔案」把第 1 步的文件放進去 → 儲存。
5. 測試十句：五句文件裡有的、三句文件裡沒有的、兩句故意刁難的；文件沒有的它要說「要問老闆」。改指示直到十句都對。
6. 右上「分享」→ 取得連結 → 給老闆或店員（他們用自己的 Google 帳號開）。
7. 交付：Gem 連結＋那份知識文件（老闆自己可以改文件，助手就跟著變）。
檢查：老闆問三個他常被問的問題，答對兩個以上才算。

### R2　Forms → Sheets → Apps Script：定時提醒／配對／彙整（workflow）　約 60 分鐘
用在：交班勾選、回診提醒、回訪名單、短班配對、no-show 前一天確認。
1. Forms 收資料：forms.google.com → 新表單 → 欄位只放必要的（例：交班勾選五項＋缺貨備註）→「回覆」分頁 →「連結到試算表」。
2. Sheets 整理：試算表第一列是欄名；若要提醒，加一欄「提醒日期」、一欄「Email」、一欄「已寄」。
3. Apps Script：試算表上方「擴充功能」→「Apps Script」→ 刪掉預設內容，貼下面的範本（改表名、欄位、信件內容）：
```javascript
function sendReminders() {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('工作表1');
  const rows = sheet.getDataRange().getValues();
  const today = new Date(); today.setHours(0,0,0,0);
  for (let i = 1; i < rows.length; i++) {
    const [name, email, dateCell, note, sent] = rows[i];      // 欄位順序依你的表
    if (sent === '已寄' || !email) continue;
    const due = new Date(dateCell); due.setHours(0,0,0,0);
    if (due.getTime() === today.getTime()) {
      MailApp.sendEmail(email, `提醒：${name}`, `今天要做：${note}\n（這封信由〔店名〕的小幫手自動寄出）`);
      sheet.getRange(i + 1, 5).setValue('已寄');
    }
  }
}
```
4. 第一次執行：上方「執行」→ 會要求授權 → 選自己的帳號 → 允許。
5. 設定定時：左側「觸發條件」→「新增觸發條件」→ 函式 sendReminders → 事件來源「時間驅動」→ 每天 → 選時段（例：上午 8–9 點）。
6. 測試：在表裡放一列今天的日期、自己的 Email，手動執行一次，收到信、「已寄」有打勾才算。
7. 彙整版（每日寄老闆）：把 for 迴圈改成把今天的列串成一段文字，寄一封給老闆。
8. 交付：表單連結（給店員填）、試算表（老闆看）、信件會自己寄。
檢查：連續兩天自動寄出、沒有重複寄。
限制：免費 Gmail 每天約 100 封（夠一家店用）；Apps Script 寄信只能用自己的 Gmail 寄。

### R3　Calendar 預約時段：讓人自己約（預約頁）　約 20 分鐘
用在：民宿回頭客直訂、工作室試教、教練排課。
1. calendar.google.com →「建立」→「預約時段」（個人帳號有基本版）。
2. 設定：時段長度、可預約的星期與時間、緩衝時間、每天上限。
3. 預約表單加欄位：姓名、電話（老闆要的最少欄位）。
4. 「開啟預約頁面」→ 複製連結。
5. 測試：用另一個帳號約一次，雙方都收到行事曆邀請。
6. 交付：預約頁連結（老闆放 LINE 官方帳號的自動回覆或 IG 簡介）。
檢查：老闆能在自己的行事曆看到預約。

### R4　Looker Studio：五個數字的儀表板（dashboard）　約 40 分鐘
用在：獲客漏斗、出席率、回訪率。
1. Sheets 先有一張乾淨的表：一列一筆（日期、階段、數量），或每週一列五個數字。
2. lookerstudio.google.com →「建立」→「報表」→ 資料來源選「Google 試算表」→ 選那張表。
3. 加五個「記分卡」（曝光、私訊、預約、到店、回流）＋一個折線圖（週趨勢）。
4. 右上「分享」→ 給老闆檢視權限；或「下載 PDF」每週傳。
5. 交付：報表連結＋每週更新 Sheets 的人是誰。
檢查：老闆看 10 秒內能說出「這週掉在哪一段」。

### R5　NotebookLM 分享筆記本：多語 SOP／知識問答（知識庫）　約 30 分鐘
用在：新人到職 SOP、外籍員工問答、家屬交接。
1. 新筆記本，放店的 SOP 文件（中文）、價目、常見狀況。
2. 問五題測試（含用員工的語言問，例：印尼文），答案要能引用來源。
3. 右上「分享」→ 加入員工的 Google 帳號（檢視者）。
4. 要影片：Studio →「影片總覽」→ 選語言 → 生成（語言支援要實測）。
5. 交付：筆記本連結＋影片連結。
檢查：新人用它回答三個 SOP 問題，不用問老闆。

## Week 7 課堂怎麼跑（分站）
0–20 五行規格（每組寫在 Demo 卡）→ app 依「AI 具體做哪個任務」指到 R1–R5 → 20–90 分站做：Gem 站（R1）、Apps Script 站（R2）、Calendar 站（R3）、Looker 站（R4）、NotebookLM 站（R5），老師與業師輪站 → 90–110 互看：哪個按鈕是多的 → 110–120 交 Demo 卡 v1、約試用。
每站一支 5 分鐘做法短片（NotebookLM 自製）＋一份範本（Google 文件／試算表副本），課前放在教材分頁。

## 紅線（寫在 Demo 卡上）
不碰醫療診斷與療效；不向移工收費；不做搶票機器人；不代寫假評論；不把客人個資放進 Gem 或 NotebookLM；Apps Script 寄信只寄給同意的人。

## 上線前要實測的（老師帳號）
R1 Gem 分享給另一個帳號能不能開；R2 觸發條件在免費帳號能不能每天跑；R3 個人帳號的預約時段功能限制；R5 影片總覽的語言。Week 7 前一週找一組先走一遍 R1＋R2。
